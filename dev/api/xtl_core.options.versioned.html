class xtl_core.options.versioned.VersionedOptions[source]#

Bases: Options

An Options model whose data carries a version tag of its own, so that data saved with an older layout is upgraded to the current one when loaded, one version at a time.

A model sets _version_path (where the tag lives in the data), _current_version (its current layout) and _upgrades (the module with its upgrade steps, registered with upgrade_step()). Older data is upgraded in from_dict(), from_json() and from_toml(); subclasses run their parents’ steps too. See the Options guide for a full example.

classmethod upgrade(data)[source]#

Upgrade data from an older version of this model to the current version, running the steps of this model and its parents in order. The result is not validated against the model, and data is left unchanged. Data without a version, from the current version or from a newer one (which logs a warning) is returned as a copy, without running any steps.

Parameters:

data (dict[str, Any]) – The data to upgrade.

Returns:

The upgraded data, with the version tag set to the model’s current version.

Raises:

TypeError – If a step doesn’t return a dict.

Return type:

Decorator to register an upgrade step on this model. The step takes the data in the layout before to and returns it in the layout of to; the function itself is returned unchanged.

Parameters:

  • to (VersionInfo | str) – The version that this step upgrades to. It can be a VersionInfo instance or a string that can be parsed into a VersionInfo.

  • model (type[Options] | None) – Optional frozen Options model of the old layout. If given, the data is validated as this model first and the step gets the model instance; keys the model doesn’t know are carried over into the result.

Returns:

The decorator.

Raises:

  • TypeError – If registered on VersionedOptions itself or on a model without a _current_version, if model isn’t a plain Options subclass, or if the function doesn’t take exactly one positional argument.

  • ValueError – If to is newer than the model’s current version, or the model already has a step to to.

Callable[[Any], Any]

classmethod upgrade_toml(s, /, *, clean=False, add_missing=False)[source]#

Upgrade TOML text from an older version of this model to the current one, keeping its comments and formatting: only what the upgrade steps change is edited, and the version tag is set to the current version (also when the text has none). New keys get their field’s description as a comment; comments on the lines above a removed key stay where they were. Text from the current version comes back unchanged.

Parameters:

  • s (str) – The TOML text.

  • clean (bool) – Write the upgraded data afresh instead (to_toml(comments=True)): the text’s own comments, formatting and unknown keys are dropped.

  • add_missing (bool) – Also add the fields that the text doesn’t have, with their values (the defaults, so the data stay the same) and descriptions; fields without a TOML value (None, unset) become commented-out lines (# key = ...  # description). Running it again adds nothing.

Returns:

The upgraded TOML text.

Raises:

  • TypeError – If the model doesn’t define a _current_version.

  • ValueError – If the text isn’t valid TOML, or is from a version newer than the current one, which can’t be downgraded.

  • OptionsValidationError – If the upgraded data isn’t valid for the model.

Return type:

str
