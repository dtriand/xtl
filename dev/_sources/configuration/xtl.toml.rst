``xtl.toml``
============
XTL reads its settings from a TOML file named ``xtl.toml``. Every setting has a default
value, so the file only needs to contain the settings you want to change.

.. _config-locations:

Config file locations
---------------------
XTL reads the first ``xtl.toml`` that exists in the following locations:

.. list-table::
   :header-rows: 1
   :widths: 10 50 40

   * - Name
     - Path
     - Autogenerated
   * - ``env``
     - the path in the ``XTL_CONFIG`` environment variable
     - yes, if set
   * - ``local``
     - ``./xtl.toml`` in the current directory
     - no
   * - ``user``
     - the user config directory, by default ``~/.config/xtl/xtl.toml`` on Linux,
       ``~/Library/Application Support/xtl/xtl.toml`` on macOS and
       ``%LOCALAPPDATA%\xtl\xtl.toml`` on Windows
     - yes
   * - ``global``
     - the XTL installation directory, for managed installations (*e.g.* on clusters)
     - yes, as a last resort

The settings are loaded the first time they are used. If no config file exists, one is
created with the default settings in the first location that can be written to. Run
``xtl.config where`` to see which file is in use.

``XTL_CONFIG`` takes precedence over all other locations, which is useful for using a
different configuration per project, job or test run:

.. set-env:: XTL_CONFIG /path/to/my-config.toml
   :windows: C:\path\to\my-config.toml

The file can have any name, as long as it is a TOML file (see
:ref:`env-xtl-config`).

File structure
--------------
The file is organised in tables, one per area of XTL, *e.g.*:

.. code-block:: toml
   :caption: ``xtl.toml``

   version = "0.2.0"

   [units]
   temperature = "K"

   [jobs.resources]
   max_jobs = 8

   [dependencies.atsas]
   path = "/opt/atsas/bin"
   modules = ["atsas/4.1.3"]

The main tables are:

- ``[units]``: physical units
- ``[jobs]``: jobs run by :mod:`xtl.jobs`, *e.g.* compute site, permissions and
  resources
- ``[dependencies]``: external programs used by XTL (*e.g.* ATSAS, autoPROC), with the
  directory of their executables (``path``) or the modules that provide them
  (``modules``)
- ``[cli]``: options for the command line utilities

All settings, with their descriptions and default values, are listed in
:class:`~xtl.config.settings.XTLSettings`, or can be printed with:

.. code-block:: console

   $ xtl.config show

Invalid files
-------------
A config file that cannot be read (invalid TOML or invalid values) is reported, and XTL
runs with the default settings instead; the file is left unchanged. Unknown keys and a
version mismatch are only reported as warnings. ``xtl.config validate`` checks a file
and lists all of its problems.

To start over from the default settings, overwrite the file with a clean one, *e.g.* for
the ``user`` location (see :doc:`../cli/xtl.config`):

.. code-block:: console

   $ xtl.config create --user --clean --force
